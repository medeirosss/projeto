# MAGI 5.9.0 + 5.9.1 — Monitoring Foundation / Light Host Checks

Base: MAGI 5.8.1 Hotfix 1.

## Incluído
- Schema PostgreSQL idempotente: security_monitor_policies, security_monitor_runs, security_monitor_checks, security_monitor_events.
- Scheduler de monitoramento (tick a cada 60 segundos), agendamento a cada 60 minutos por Campaign, sem sobreposição.
- Monitoramento opt-in, desabilitado por padrão.
- Probes Nmap host-only não autenticados para IPs privados conhecidos no último baseline da Campaign.
- Despacho limitado a 5 novos jobs por tick; máximo de 254 hosts por baseline.
- Resultado inconclusivo se Runner/Nmap não trouxer estado explícito do host; falhas operacionais não geram alerta de indisponibilidade.
- Evento HOST_UNREACHABLE somente após duas observações 'down' consecutivas; RECOVERED quando uma observação 'up' sucede uma 'down'.
- APIs GET/POST /api/security-monitoring/campaigns/{uuid}; botão Monitoring na tabela Campaign.

## Não incluído nesta entrega
- Diferenças de portas/serviços; verificação de novos hosts fora do baseline; autenticação; notificações externas.
- Não foi executado teste integrado com PostgreSQL/Runner Windows. É uma build candidata a homologação.

## Homologação
1. Faça backup do banco e preserve a versão anterior.
2. Execute e encerre uma Campaign para criar o baseline.
3. Clique Monitoring e habilite. Confirme que surgem jobs nmap_discovery para os IPs conhecidos (no máximo 5 por minuto).
4. Confirme que um erro do Runner aparece como inconclusive e não como host offline.
5. Aguarde duas execuções com estados explícitos down para testar o alerta de indisponibilidade.
6. Desabilite Monitoring e verifique que novas execuções não são criadas.

## Observação
O estado `up/down` depende da estrutura de resultado retornada pelo executor Nmap do Runner. Se o executor retornar um formato diferente, a leitura será inconclusiva e precisará ser ajustada após o primeiro teste.
